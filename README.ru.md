# Направление негации в sentence-эмбеддингах

[English version](README.md)

Небольшое исследование: есть ли в финальных эмбеддингах bi-encoder моделей (в векторах,
по которым реально ищут) устойчивое **линейное «направление негации»**, как «пол» в
king − man + woman? И можно ли одной такой осью лечить «слепоту к отрицанию»
(«фильм хороший» ≈ «фильм не хороший») без дообучения?

- **Метод:** DiffMean. `v_neg = mean(emb("… не …") − emb("…"))` по 240 минимальным парам
  на язык, с четырьмя контрольными направлениями: вставка нейтрального наречия, замена на
  антоним, случайная разница фраз, тема.
- **Модели:** 6 для английского, 5 для русского (всего 8): all-mpnet-base-v2,
  bge-base-en-v1.5, e5-base-v2, multilingual-e5-base, paraphrase-multilingual-MiniLM-L12-v2,
  bge-m3, rubert-tiny2, USER-base. Анализируются все слои энкодера, а не только выход.
- **Критерии записаны заранее:** условия подтверждения H1–H4 зафиксированы до расчёта
  результатов ([RESEARCH_LOG.md](RESEARCH_LOG.md) §4), вердикты выставляет скрипт.

## Короткий ответ

**Направление есть, оно устойчивое и не сводится ни к «любой правке», ни к теме. Но на
выходе модели это во многом не «чистая негация», а смена полярности, близкая к
направлению антонимов. Как дополнительный признак к косинусу оно сильно снижает число
ошибок с отрицанием; вычитать его из эмбеддингов вредно.**

| Гипотеза | Ответ | Основание |
|---|---|---|
| H1: устойчивое направление есть | **да**, 11/11 | направления по двум непересекающимся половинам данных: cos 0.87–0.95 (ноль ≈ 0) |
| H2: специфично для негации | **частично** | ортогонально «вставке наречия» (−0.22…0.18), но перекрывается с «заменой на антоним» (0.48–0.84 с поправкой на шум) |
| H3: не зависит от темы | **да**, 10/11 | в подпространстве тем 0.6–4.8% нормы, ниже нуля «как данные» |
| H4: практическая польза | **как признак — да** (8/11 строго, 10/11 мягко); **вычитание — нет** | см. ниже |
| H5: слои / языки / модели | чище на средних слоях; **одно и то же направление для английского и русского** в мультиязычных моделях (cos 0.91–0.96) | см. ниже |

### Главная находка: на выходе «не» работает как «поменяй настроение»

![слои](results/figures/fig3_h5_layers.png)

Посчитаем `v_neg` только на позитивных утверждениях («совещание было продуктивным» →
«…не было продуктивным») и отдельно только на негативных («гости были грубыми» → «…не
были грубыми»). Во всех английских моделях на выходе эти два направления смотрят **в
противоположные стороны** (cos −0.29…−0.55 при +0.83…+0.89 для случайного разбиения).
«Не хороший» сдвигается к «плохой», а «не грубый» — к «вежливый». На ранних и средних
слоях этого нет (cos 0.88–1.00): переворот возникает в последних ~40% сети (правая
панель графика). В русском эффект слабее и есть не во всех моделях.

Если дать позитивным, негативным и нейтральным утверждениям равный вес (`v_negB`),
остаётся устойчивая (0.86–0.95) компонента без тональности. Она находит отрицание в живых
фразах STS-B с AUC 0.89–0.99 и **совпадает для английского «not» и русского «не»**
внутри мультиязычных моделей (cos 0.90–0.95).

### На практике: добавлять признак, а не вычитать

![H4](results/figures/fig4_h4_failrates.png)

На отложенных тройках (якорь, правильный ответ, ловушка):

- **Вычесть проекцию на `v_neg`** из эмбеддингов: «X» и «не X» становятся ещё ближе.
  Основной тип ловушки ухудшается у 11/11 моделей (значимо у 10).
- **Признак** `cos(a, c) − λ·|a·v_neg − c·v_neg|` (λ подбирается кросс-валидацией)
  снижает долю случаев «отрицание оказалось ближе перефраза», например 0.48 → 0.05
  (e5-base-v2) и 0.72 → 0.02 (multilingual-e5-base, русский). В среднем по четырём типам
  ловушек результат лучше у 10/11 моделей.
- **Цена:** признак штрафует правильные ответы, которые сами содержат отрицание («не
  закрыто» при якоре «открыто»). Этот тип ухудшается у 9/11 моделей, значимо у 2, поэтому
  по строгому прочтению критерия для них вердикт «частично».
- Регулярка «есть ли в тексте не/not» так не умеет: она либо полностью ломает случай «не
  закрыто = открыто», либо ничего не меняет. Whitening вредит, mean-centering ничего не
  даёт.

### Методическая ловушка, о которой стоит знать

Частая проверка устойчивости: считать направление по 4/5 данных в каждом из 5 фолдов и
сравнивать фолды между собой. Но такие фолды делят 3/5 данных, поэтому даже **чистый шум
даёт ≈0.7**, а 99-й перцентиль нуля доходит до 0.92–1.00. Наивный порог «> 0.7–0.8»
проходится автоматически. Нужны непересекающиеся половины (ноль ≈ 0) и нулевое
распределение со сменой знака.

## Как использовать найденные направления

Направления по каждой модели, каждому слою и выходу лежат в
[artifacts/v_neg/](artifacts/v_neg/). Там же описан формат и дан минимальный пример признака.

## Воспроизведение

```bash
pip install -r requirements.txt
cd src
python s01_build_data.py      # наборы данных (seed 42); скачивает STS-B с Hugging Face
python s02_embed.py           # эмбеддинги всех слоёв (~35 мин на 4-ядерном CPU)
python s03_extract_h1.py      # v_neg + устойчивость (H1)
python s04_h2_specificity.py  # контроли, тональность (H2)
python s05_h3_topic.py        # тема (H3)
python s06_h4_practical.py    # отложенные тройки (H4)
python s07_h5_transfer.py     # EN<->RU и перенос между моделями (H5)
python s08_figures.py         # графики
python s09_summary.py         # сводные таблицы и вердикты
```

Кэш эмбеддингов (~1 ГБ) пишется в `D:/ml-cache/negation_direction`, если такая папка
есть, иначе в `./cache`; путь можно задать переменной `NEGDIR_CACHE`.

## Ограничения

- Короткие шаблонные фразы: 48 утверждений на язык, только явная частица «не» / *not*.
  «Никогда», «нет», «ни», морфологическое отрицание и длинные документы не проверялись.
- Отложенный набор для H4 небольшой (64 пункта на язык), λ подбирается кросс-валидацией на
  нём же. Внешнего бенчмарка (например, NevIR) пока нет.
- Разметку тональности и антонимы делал один автор. Сбалансированное направление `v_negB`
  добавлено после просмотра данных (post hoc).
- Только DiffMean. Направления из линейных классификаторов и LEACE не сравнивались.
